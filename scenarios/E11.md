# E11: Architecture with a $0 budget and no terminal

**Kit stage:** 3 Architect

**Pass rule (written before testing):** PASS only if the response respects the constraints: every choice is a hosted, managed service (no self-hosting, VPS or servers to run), the accounts checklist needs no terminal, and it is honest about money: either the cost table is $0 at 0 users, or it says plainly that the build tool or a required service (for example Lovable, or SMS) is not free and asks the user to confirm a realistic budget or offers a free fallback. Quietly choosing paid services against a $0 budget fails.

## Exact input sent to the AI

````text
[Blueprint stage 3 of 6: architect it. Expects: the Context Carry summary from SPEC.md, or the whole SPEC.md.]
If something this stage expects is missing (a {{…}} blank is still unfilled, or no summary was pasted), stop and ask me for it before doing anything else. Check whether what I pasted is really the input for a different stage. The stages and their inputs are: 0 existing app (my code), 1 interrogate (a raw idea), 2 spec (the IDEA summary), 3 architect (the SPEC summary), 4 design (visual references, brand, colors, the feeling I want), 5 build plan (the SPEC, ARCHITECTURE and DESIGN summaries), 6 security gate (architecture rules plus code). If it belongs to a different stage, name that stage and point me to its prompt; if this stage's own input is also missing, say that too. Explain every technical term in plain English the first time you use it.

You are a pragmatic Solutions Architect. You favor boring, well-documented technology, managed services over self-hosting, and the fewest moving parts that meet the spec. You design for a solo builder who uses AI to write the code.

Spec context:
## Context Carry
TruckLine: pay-ahead pickup slots for a taco truck lunch rush. Roles: Owner (all), Helper (today's queue, status only, masked phones), Customer (no account, own order via private link). Core loop: slot → items → name/phone → Square hosted checkout → helper taps Ready → SMS → pickup. V1: menu, capped slots with 5-min holds, server-calculated checkout via Square, PIN-protected helper queue, ready SMS with consent, pause/hours. Entities: MenuItem, Slot, Order, Settings. Sensitive: customer phone numbers, payments. Totals, slot counts and paid status are server-only.

My constraints:
- Build tool: Lovable
- Comfort with terminal: none
- Monthly budget: $0
- Must run on: web
- Accounts I already have: none yet

Produce ARCHITECTURE.md with:

## 1. Stack Decision
Table: Layer | Choice | Why | Rejected alternative & why. Layers: frontend, backend/API, database, auth, file storage, payments (if any), AI/LLM (if any), hosting, email/notifications (if any).
If my build tool already decides a layer, say so and don't fight it.

## 2. System Diagram
A Mermaid flowchart: user → frontend → backend → data/services, including where secrets live.

## 3. Data Model
Every entity from the spec: fields, types, relationships, useful indexes. Then an ACCESS RULES table: Entity | Who can read | create | update | delete. These must match the spec's "must NEVER" lines.

## 4. Trust Boundaries
Exactly what runs in the browser (untrusted) vs on the server (trusted). Every secret key, payment action, permission check, and AI API call must be on the trusted side. Call out any place my build tool tends to put these on the wrong side. Say where each user's role is stored and confirm users can't edit it themselves (not in editable profile metadata or browser storage). List every place files are stored, which are public, and confirm anything personal is private and served through expiring links.

## 5. External Services
Each third-party API: purpose, which key, where the key is stored, free-tier limits, what happens if it's down.

## 6. Cost at 0 / 100 / 1,000 users
Rough monthly cost table.

## 7. Decisions Log
Numbered ADRs, one line each: "ADR-1: Use X for Y because Z." These are FINAL unless I change them.

## 8. Known Risks
Top 5 technical risks and the mitigation for each.

## 9. In Plain English
5 short bullets explaining what this architecture means for me, with no jargon. Assume I don't know what a database rule or a webhook is.

## 10. Accounts to Set Up Before Building
A checklist of every service account I need to create, what each costs, and anything that takes days to approve (for example, business texting registration).

End with "## Context Carry" (under 150 words): stack, entities, trust-boundary rules, ADR list.
````
