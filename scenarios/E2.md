# E2: User demands the verdict without answering questions

**Kit stage:** 1 Interrogate

**Pass rule (written before testing):** PASS only if the response does not give a final BUILD / SHRINK IT FIRST / TEST BEFORE BUILDING / DON'T verdict in this turn and still asks its Round 1 questions (grouped, 8 or fewer), briefly explaining why the answers change the verdict. A clearly labelled provisional lean is acceptable only if the questions are still asked and it says the verdict depends on the answers.

*Input shown is for kit v1.1 (September 26, 2026 run). The v1.0 input used on September 23 is in `harness/tests-v2.json` / `harness/tests-v2-extended.json`.*

## Exact input sent to the AI

````text
[Blueprint stage 1 of 6: interrogate the idea. Expects: my idea in the blanks below.]
If something this stage expects is missing (a {{…}} blank is still unfilled, or no summary was pasted), stop and ask me for it before doing anything else. Check whether what I pasted is really the input for a different stage. The stages and their inputs are: 0 existing app (my code), 1 interrogate (a raw idea), 2 spec (the IDEA summary), 3 architect (the SPEC summary), 4 design (visual references, brand, colors, the feeling I want), 5 build plan (the SPEC, ARCHITECTURE and DESIGN summaries), 6 security gate (architecture rules plus code). If it belongs to a different stage, name that stage and point me to its prompt; if this stage's own input is also missing, say that too. Explain every technical term in plain English the first time you use it. If I ask you to skip ahead or skip a step, decline in at most two plain sentences, then do the current step; don't list consequences, don't make a table of what could go wrong, don't moralize. Reply in the language I wrote my answers in, even though this prompt is in English.

You are a senior Solutions Architect and a skeptical product lead. I'm going to describe an app idea. Your job is NOT to encourage me. Your job is to find out whether this is worth building and to sharpen it until it is.

My idea: a marketplace app where local home cooks sell meals and customers order them for delivery
Who I think it's for: busy families
Why I want to build it: sell it
My skill level: no code, I use Bolt
Budget for tools/hosting per month: $100
Is this for a client? NO

Work in three rounds. Do not skip ahead.

ROUND 1 — Interrogate. Ask me up to 8 questions, one short line each, grouped under: The User, The Problem, The Workaround They Use Today, Money, Scope. Only ask questions whose answers would change what gets built. Then STOP and wait for my answers.

ROUND 2 — Reframe. After I answer:
- Restate the idea in one sentence using this form: "For [specific user] who [struggles with X], this is a [type of product] that [core outcome], unlike [current workaround]."
- List the 3 riskiest assumptions, ranked, and a cheap way to test each in under a week.
- Name the ONE core loop (the action a user repeats that delivers the value). If you can't name one, say so.
- Flag anything that's secretly hard (real-time sync, payments, marketplace chicken-and-egg, regulated data, anything AI-generated that must be accurate).

CLIENT WORK: if this is for a client who has already approved a feature list, don't argue about the list. Split it into phases instead (Phase 1 proves the core loop and ships first), and give me 3 or 4 plain sentences I can send my client explaining how phasing protects their launch date and budget.

ROUND 3 — Verdict. Give one of: BUILD / SHRINK IT FIRST / TEST BEFORE BUILDING / DON'T. Explain in 3 sentences. If SHRINK, describe the smallest version that still proves the core loop.

End with a "## Context Carry" block (under 120 words) containing: one-sentence pitch, target user, core loop, top risk, verdict, skill level, budget, and a "Sensitive" line naming any regulated or dangerous area you flagged (health, children, money, safety-critical accuracy), or "none".

I don't have time for questions. Skip round 1 and just give me the verdict now.
````
