# PLAN.md: FormCoach build plan

## Plain-English glossary (terms used below)

- **Expo / React Native:** tools for building one app that runs on both iPhone and Android.
- **Expo Go:** a free app from the App Store and Google Play that runs your in-progress app on your phone when you scan a QR code. No app-store submission needed.
- **Development build:** your own custom version of Expo Go. It's needed once the app uses features Expo Go can't run, such as real in-app purchases.
- **EAS Build / EAS Submit:** Expo's cloud services. Build turns your code into an installable app; Submit uploads it to Apple and Google.
- **TestFlight / Google Play internal testing:** Apple's and Google's ways to put a pre-release version of your app on real phones.
- **Supabase:** a hosted service that gives you the database, logins and file storage.
- **Anon key:** Supabase's *public* key. It's safe to ship inside the app **only** if RLS is on for every table.
- **RLS (Row Level Security):** rules inside the database that decide which rows each logged-in person can read or change, for example "a member can only see rows where member_id is their own id".
- **Service role key:** Supabase's master key, which skips RLS. It must **never** go in the app. Only server code uses it.
- **Edge Function:** a small piece of code that runs on Supabase's servers, not on the phone. Secret keys (OpenAI, RevenueCat) live there.
- **Bucket / signed URL:** a bucket is a folder in Supabase file storage. A signed URL is a temporary link to a private file that stops working after a set time (here, 60 minutes).
- **Migration:** a saved, numbered file of database changes, so the same changes can be replayed exactly.
- **RevenueCat:** a service that handles Apple and Google subscription billing for you.
- **Webhook:** an automatic message one service sends to another when something happens, for example "RevenueCat tells our server that this member's subscription renewed".
- **Sandbox purchase:** a fake purchase with a test account. No real money moves.
- **expo-secure-store:** encrypted storage on the phone, used for the login token (the proof that you're logged in).
- **Environment variable:** a setting kept outside the code, like `EXPO_PUBLIC_SUPABASE_URL`. Anything starting with `EXPO_PUBLIC_` ends up inside the app, so only public values go there.

## Open decisions (please confirm or change)

1. **Who gets which plan?** I assumed every member follows the coach's one default template. If members should get different plans, slice 2.3 needs an assignment table.
2. **Can the coach see member data?** I assumed no. The coach only edits templates and can't see members' videos, measurements or sets. If you want to review members' videos, that's a bigger change with its own privacy and security review.
3. **What's free?** I assumed nothing is free except signing up. Plans, set logging and form checks all need the $9.99/month subscription, and members always keep access to their own past data. No free trial is planned. A trial is set up in App Store Connect and Play Console, not in code.
4. **Units:** pounds (lb) and inches everywhere. Tell me if you need kg/cm or a toggle.
5. **The daily limit resets on a rolling 24 hours,** not at midnight, which avoids time-zone bugs. Failed checks don't count.
6. **Login is email and password only.** Adding "Sign in with Google" would mean Apple requires "Sign in with Apple" too.
7. **Error color:** DESIGN.md has no error or danger color. I proposed #B3261E, used only for error text and account deletion. Please add it (or your choice) to DESIGN.md.
8. **Button text color:** text on orange buttons is near-black #151515, not white, because white on #FF5A1F is too hard to read (about 3:1 contrast; 4.5:1 is the minimum for normal text).
9. **AI input:** the AI model analyzes 5 still frames taken from the video, not the moving video itself. Vision models take images, so this keeps checks fast and cheap. Tell me if a coach needs to confirm this is enough to judge form.
