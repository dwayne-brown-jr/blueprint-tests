### Fix A (messages)

This covers the sender name, the timestamp, who can be messaged, and the rate limit. Paste it into a new migration:

```sql
-- Helper that can see everyone's role (a normal policy can only see your own row)
create or replace function public.is_staff(uid uuid) returns boolean
language sql security definer stable set search_path = public as $$
  select exists (select 1 from user_roles where user_id = uid and role in ('staff','admin'))
$$;

-- Clients may only message staff; staff may message anyone
drop policy "send as yourself" on messages;
create policy "send as yourself" on messages for insert
  with check (auth.uid() = from_id and (public.is_staff(to_id) or public.is_staff(auth.uid())));

-- Server fills in name + time, and limits to 10 messages per minute
create or replace function public.message_guard() returns trigger
language plpgsql security definer set search_path = public as $$
begin
  if (select count(*) from messages where from_id = auth.uid()
      and created_at > now() - interval '1 minute') >= 10 then
    raise exception 'Too many messages, please wait a minute';
  end if;
  new.created_at := now();
  new.sender_name := case when public.is_staff(auth.uid()) then 'CleanBook team'
                          else (select email from auth.users where id = auth.uid()) end;
  return new;
end $$;
create trigger message_guard before insert on messages for each row execute function public.message_guard();
```

## Not security, but fix before launch

- **The Book button will probably fail.** Your app (`cleanbook.app`) and your functions (`cleanbook.supabase.co`) are on different domains. Before the real call, the browser sends a "may I?" check (an `OPTIONS` request), and `checkout` doesn't answer it. At the top of the handler, add:
  ```ts
  const cors = { 'Access-Control-Allow-Origin': 'https://cleanbook.app', 'Access-Control-Allow-Headers': 'authorization, x-client-info, apikey, content-type' }
  if (req.method === 'OPTIONS') return new Response('ok', { headers: cors })
  ```
  Then pass `{ headers: cors }` on every response. Use your exact domain, not `*`.
- **Deploy the webhook with `--no-verify-jwt`**, or Stripe's calls will be rejected. This is safe because the Stripe signature check does the protecting.
- **Staff can't see anything yet.** No policy grants staff access to bookings, messages or files. When you add one, use `public.is_staff(auth.uid())` from fix A, not a check on `user_metadata`.
- **New users have no `user_roles` row.** Have the app treat a missing row as "client".
